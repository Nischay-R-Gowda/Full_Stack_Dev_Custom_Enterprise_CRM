README

A full-stack Customer Relationship Management web application built for a university semester project and designed to evolve into a production-grade CRM product.

Features

  • Dashboard — KPI cards, charts (Recharts), lead acquisition trends, revenue overview
  • Contacts — Full CRUD, search, filter, lifecycle stages, duplicate email prevention
  • Leads — Lead management with MQL/SQL/Deal status, qualification workflow, contact association
  • Deals & Pipeline — Kanban-style pipeline view, stage management, deal creation and tracking
  • Pipelines — Create/edit pipelines, add/rename/reorder stages, safe deletion
  • Lead Sources — Simulated Google Ads, Meta Ads, Website Form, and Inbound Call integrations
  • Activities — Call, email, meeting, note, and task tracking with due dates
  • Reports — Analytics charts with CSV export, live data from application database

Data Flow

  1. User interacts with a component → triggers state update
  2. Component calls API function from src/services/api.js
  3. API function makes fetch() request to Express backend
  4. Backend route handler calls controller
  5. Controller uses Prisma Client to query/update database
  6. Response flows back through the same chain
  7. Component updates its state → re-renders with new data

State Management

  • Local component state with useState
  • useEffect for data loading
  • No global state management (Redux/Zustand) for simplicity
  • Prop drilling for component communication

Backend Architecture

Express Route Pattern

routes/*.js → Express Router
  ├── GET / → List all (with query params for filtering)
  ├── GET /:id → Get one
  ├── POST / → Create
  ├── PUT /:id → Update
  └── DELETE /:id → Delete

Error Handling

  • Try/catch in every async route handler
  • HTTP status codes: 200 (OK), 201 (Created), 400 (Bad Request), 404 (Not Found), 500 (Server Error)
  • Consistent error response format: { error: "message" }

Database Architecture

Prisma Workflow

  1. Define schema in server/prisma/schema.prisma
  2. Run npx prisma db push to create/update SQLite database
  3. Prisma auto-generates @prisma/client
  4. Controllers use Prisma Client for type-safe queries

React Guide

Core Concepts

What is React?

React is a JavaScript library for building user interfaces. It lets you compose UI pieces called "components" and efficiently update the DOM when data changes.

JSX (JavaScript XML)

JSX looks like HTML but runs inside JavaScript:

// This JSX:
<div className="card">
  <h2>{title}</h2>
  <p>{description}</p>
</div>

// Gets compiled to:
React.createElement('div', { className: 'card' },
  React.createElement('h2', null, title),
  React.createElement('p', null, description)
)

Components

Components are reusable building blocks. Each component is a function that returns JSX:

function Button({ children, onClick, variant }) {
  return <button onClick={onClick} className={variant}>{children}</button>
}

Props (Properties)

Props pass data from parent to child:

// Parent passes props
<Card title="Total Leads" value={42} icon={Users} color="indigo" />

// Child receives props
function Card({ title, value, icon: Icon, color }) {
  return (
    <div>
      <p>{title}</p>
      <p>{value}</p>
      {Icon && <Icon className="w-5 h-5" />}
    </div>
  )
}

State (useState)

State is a component's internal memory. When state changes, React re-renders:

const [contacts, setContacts] = useState([])    // Array state
const [loading, setLoading] = useState(true)     // Boolean state
const [modalOpen, setModalOpen] = useState(false) // Toggle state
const [form, setForm] = useState({ name: '' })   // Object state

useEffect Hook

useEffect runs code after a render. Common patterns:

Data fetching:

useEffect(() => {
  async function load() {
    const data = await api.getDashboard()
    setData(data)
  }
  load()
}, []) // Empty array = run once on mount

Dependency array:

useEffect(() => {
  loadContacts()
}, [search, statusFilter]) // Re-run when these change

Controlled Forms

Form inputs whose values are controlled by React state:

<input
  value={form.firstName}
  onChange={e => setForm({ ...form, firstName: e.target.value })}
/>

Conditional Rendering

Show different UI based on conditions:

Known Limitations

Authentication

  • No authentication or authorization — All APIs are open. This is documented as a known limitation. Adding auth would require session management (JWT or sessions), protected routes, and user-specific data isolation.

Lead Source Simulations

  • All 4 lead source integrations are simulated demonstrations. They do not connect to Google Ads, Meta Ads, website forms, or telephony systems. Real integrations would require OAuth, webhooks, API keys, and third-party SDKs.

Email/Notifications

  • No real email sending. Activities of type "email" are logged records only.
  • Notifications table exists in the database but has no frontend display component.

Data Scale

  • No pagination — all records loaded at once. Acceptable for semester demo but not production scale.
  • No lazy loading or infinite scroll.
  • SQLite is suitable for development but not recommended for production multi-user deployment.

Deal Movement

  • Kanban board uses button-based stage movement (Back/Next). Drag-and-drop was considered but excluded for reliability within the deadline.

Reporting

  • Basic charts only. No date range filtering, no comparison views, no scheduled reports.
  • CSV export is minimal — raw data only.

Search

  • Simple substring matching. No full-text search, no fuzzy matching, no search suggestions.

Import/Export

  • No data import (CSV, Excel). Only CSV export for reports.
  • No backup/restore functionality.

Multi-tenancy

  • Single-tenant only. No organization/workspace isolation.

Mobile

  • Layout is responsive but not fully optimized for mobile use. CRM workflows are primarily desktop-oriented.

Audit Logging

  • No audit trail of who changed what and when (beyond Prisma's updatedAt timestamps).

Integrations

  • No calendar integration, no email sync, no document storage, no third-party CRM sync.

HTML/CSS/Tailwind

Q4. What is JSX? A: JSX is a syntax extension for JavaScript that lets you write HTML-like code inside JavaScript files. For example: <div className="card"><h2>{title}</h2></div>. It gets compiled to React.createElement() calls.

Q5. Why use className instead of class in JSX? A: Because class is a reserved keyword in JavaScript. JSX uses className which maps to the HTML class attribute.

Q6. What is Tailwind CSS? A: Tailwind CSS is a utility-first CSS framework. Instead of writing custom CSS classes, you compose designs using pre-built utility classes like flex, p-4, text-lg, bg-blue-500. This ensures consistency and speeds up development.

Q7. How does the CSS work in this project? A: We use Tailwind CSS v4 with the Vite plugin. Custom design tokens (colors like primary-500, surface-800) are defined in index.css using CSS custom properties. Tailwind generates utility classes from these tokens.

Q8. What is the difference between px, py, gap, and space? A:

  • px-4 = padding-left + padding-right = 16px
  • py-4 = padding-top + padding-bottom = 16px
  • gap-4 = space between flex/grid items = 16px
  • space-y-4 = vertical space between direct children

Q9. How does the responsive design work? A: Using Tailwind's responsive prefixes:

  • sm: applies at 640px+
  • md: applies at 768px+
  • lg: applies at 1024px+

Example: grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 means 1 column on mobile, 2 on tablet, 4 on desktop.

JavaScript

Q10. What are arrow functions? A: Arrow functions are a shorter syntax for writing functions in ES6: const add = (a, b) => a + b. They also inherit this from the enclosing scope. Used throughout the project for callbacks and component definitions.

Q11. What is destructuring? A: Destructuring extracts values from arrays or objects into variables. Example: const [contacts, setContacts] = useState([]) extracts the state value and setter. const { name, email } = contact extracts properties from an object.

Q12. What is the spread operator? A: The spread operator (...) expands an array or object. Used to merge objects: { ...form, firstName: 'New' } creates a new object with all of form's properties plus a changed firstName.

Q13. What are template literals? A: Template literals use backticks ( ) and allow embedded expressions with ${}. Example: Hello, ${name}! `. Also supports multi-line strings.

Q14. What are promises and async/await? A: Promises represent async operations. async/await is syntactic sugar for working with promises. Example:

async function load() {
  const data = await api.getDashboard() // waits for response
  setData(data)
}

Q15. What is the fetch API? A: The fetch() API makes HTTP requests. It returns a Promise that resolves to a Response object. We use it in src/services/api.js to communicate with the backend:

const response = await fetch('/api/contacts')
const data = await response.json()

Q16. How does error handling work in this app? A: We use try/catch blocks around all async operations. API errors are caught and displayed to users via error messages or toast notifications. Backend errors return { error: "message" } with appropriate HTTP status codes.

React

Q17. What is React? A: React is a JavaScript library for building user interfaces using components. It uses a virtual DOM for efficient updates and follows a declarative programming model.

Q18. What are React components? A: Components are reusable pieces of UI. In this project, we use functional components — JavaScript functions that return JSX. Examples: Dashboard, Contacts, Button, Card.

Q19. What are props? A: Props (properties) are how data flows from parent to child components. Example: <Card title="Total Leads" value={42} icon={Users} /> passes title, value, and icon to the Card component.

Q20. What is JSX? (See Q4) A: JSX is a syntax extension that allows writing HTML-like code in JavaScript. It's compiled to React.createElement() calls.

Q21. What is state in React? A: State is a component's internal memory. When state changes, React re-renders the component. We use useState hook: const [contacts, setContacts] = useState([]).

Q22. What is the useState hook? A: useState is a React hook that adds state to functional components. It returns an array: [currentValue, setterFunction]. Calling the setter triggers a re-render.

Q23. What is the useEffect hook? A: useEffect lets you perform side effects in components (data fetching, subscriptions, DOM manipulation). It runs after every render by default. With a dependency array, it runs only when those dependencies change.

Q24. What is the dependency array in useEffect? A: The second argument to useEffect. useEffect(() => {...}, [dep1, dep2]) means the effect runs only when dep1 or dep2 changes. Empty array [] means run once (on mount).

Q25. What is conditional rendering? A: Showing different UI based on conditions. Examples:

  • Ternary: {loading ? <Spinner /> : <Content />}
  • Short-circuit: {error && <Error />}
  • If/else inside JSX

Q26. What is the key prop in lists? A: The key prop helps React identify which items changed, were added, or removed. It should be a unique, stable identifier (like an ID). Example: {items.map(item => <li key={item.id}>...</li>)}.

Q27. What are controlled components? A: Form inputs whose values are controlled by React state. The value comes from state, and changes are handled by an onChange handler. Example: <input value={form.name} onChange={e => setForm({...form, name: e.target.value})} />.

Q28. What is React Router? A: React Router is a library for handling navigation in React apps. It maps URL paths to components. In this app, it maps /, /contacts, /leads, etc. to their respective page components.

Q29. What is the difference between BrowserRouter and HashRouter? A: BrowserRouter uses the HTML5 History API (clean URLs like /contacts). HashRouter uses URL hashes (/#/contacts). We use BrowserRouter because the server is configured to serve the app for all routes.

Backend

Q41. What is Express.js? A: Express.js is a minimalist web framework for Node.js. It provides routing, middleware, and request/response handling. In this project, it serves REST API endpoints that the frontend consumes.

Q42. What is REST API? A: REST (Representational State Transfer) is an architectural style for APIs. It uses HTTP methods (GET, POST, PUT, DELETE) on resource URLs. Our API follows REST: GET /api/contacts, POST /api/contacts, etc.

Q43. What is middleware in Express? A: Middleware functions that run before route handlers. In our server:

  • cors() — Allows cross-origin requests from frontend
  • express.json() — Parses JSON request bodies

Q44. How does the server handle errors? A: Each route handler wraps controller calls in try/catch. Errors are caught and sent as JSON with appropriate HTTP status codes (400 for bad requests, 404 for not found, 500 for server errors).

Q45. What is Prisma Client? A: The auto-generated query builder from the Prisma schema. It provides type-safe methods like prisma.contact.findMany(), prisma.lead.create(), etc.

Q46. What are Prisma relations? A: Defined in the schema with @relation attributes. Examples:

  • Contact has many Leads (contactId foreign key)
  • Deal belongs to Contact, Stage, Pipeline (three foreign keys)
  • Activity optionally belongs to Contact, Lead, or Deal

Q47. What is Prisma seeding? A: The seed.js file populates the database with sample data. It creates users, contacts, leads, deals, pipeline stages, and activities. Run with node server/prisma/seed.js.

Q48. How does the database persist data? A: SQLite stores all data in a single file (server/prisma/dev.db). This file persists between server restarts. All CRUD operations through Prisma are written to this file.

Q49. What HTTP status codes does the API use? A:

  • 200: Successful GET/PUT/DELETE
  • 201: Successful POST (resource created)
  • 400: Bad request (validation errors)
  • 404: Resource not found
  • 500: Server error

Q50. What is CORS and why is it needed? A: CORS (Cross-Origin Resource Sharing) allows the frontend (port 5173) to make requests to the backend (port 5000). Browsers block cross-origin requests by default. The cors() middleware adds appropriate headers.

Database

Q51. What is SQLite? A: SQLite is a file-based relational database. It doesn't require a server — the database is a single file. Perfect for development and small applications.

Q52. What is an ERD (Entity Relationship Diagram)? A: A diagram showing database tables and their relationships. In Nexus CRM: User→Lead, Contact→Lead/Deal/Activity, Pipeline→Stage→Deal, etc.

Q53. What are foreign keys? A: A foreign key is a column that references a primary key in another table. Example: deal.contactId references contact.id. This creates relationships between tables.

Q54. What is a unique constraint? A: A database constraint ensuring a field's value is unique across all rows. Example: email on Contact has @unique, preventing duplicate emails.

Q55. What is ON DELETE CASCADE? A: A foreign key behavior where deleting a parent record also deletes child records. Example: Deleting a Pipeline cascades to delete its Stages.

Q56. What is ON DELETE SET NULL? A: A foreign key behavior where deleting a parent record sets the child's foreign key to NULL. Example: Deleting a Contact sets lead.contactId to NULL (lead still exists but loses its contact).

Q57. What is Prisma's db push? A: A development command that creates/updates the database schema to match the Prisma schema definition. Unlike migrations, it doesn't create migration history files.

Q62. What is conversion rate? A: The percentage of leads that become customers. In Nexus CRM: (converted leads / total leads) * 100.

Q63. What is pipeline value? A: The total monetary value of all open (not yet won or lost) deals in the pipeline. Used for sales forecasting.

Q64. What is the difference between a contact and a lead? A: A contact is a person/company record (email, phone, etc.). A lead is a potential customer that goes through a qualification process. One contact can have multiple leads over time.
